# Management-plane CGI discovery

Firmware: V100SP11240725. Operator-provided model: ONT-S207CW-62TS-SE.
The UI reports generic device information; MAC and serial, retained privately,
are the identity anchors. Capture started from repository revision `545cd5c`
on 2026-09-17. No IP, password, controller networking, or restore changes were
performed. Reboot has not been tested during this discovery.

## Evidence levels

1. **EXTERNAL REVERSE ENGINEERING**: the approved
   [reference revision](https://github.com/emesix/ONT-S207CW-62TS-SE/tree/59cea3e2b57c8793ceb2062f619a54aeec65293c)
   identifies likely endpoints. It is not a protocol specification. Its
   firmware source path strings are not available handler implementations.
2. **OBSERVED IN UI SOURCE ONLY**: actual HTML/JavaScript establishes form
   serialization and intended success handling, not runtime mutation semantics.
3. **CONFIRMED BY LIVE GET**: authenticated pages were downloaded from this
   device and firmware, with HTTP 200 and `text/html`.
4. **CONFIRMED BY LIVE POST**: exactly one save command returned HTTP 200,
   `application/json`, and `{"code":0,"data":""}`. Subsequent reads confirmed
   unchanged MAC/serial, management page, port settings, and VLAN memberships.

## Contracts observed on the device

| Operation | Request | Fields | Evidence |
| --- | --- | --- | --- |
| Read management network | GET `/ip.cgi` | `page=inside` | LIVE GET |
| Read user form | GET `/user.cgi` | `page=inside` | LIVE GET |
| Read system controls | GET `/dev.cgi` | `page=inside` | LIVE GET |
| Change static network | POST `/ip.cgi` | `ip`, `netmask`, `gateway`, `cmd=ip`, `dhcp_state=0`, `page=inside` | UI SOURCE ONLY |
| Change account password | POST `/user.cgi` | `mname`, `mpass`, `mpass2`, `page=inside` | UI SOURCE ONLY |
| Save configuration | POST `/syscmd.cgi` | `cmd=saveconfig`, `page=inside` | LIVE POST |
| Reboot | POST `/syscmd.cgi` | `cmd=reboot`, `page=inside` | UI SOURCE ONLY; NOT TESTED |

The root page's `httpPostGet` helper appends `page=inside`. GETs generated by
that helper also have a millisecond `stamp`; captured GETs succeeded without
it, so it is not established as required. POST uses
`application/x-www-form-urlencoded`; `serializeElement` percent-encodes keys
and values. `getElements` includes inputs and selects; `inputSelect` omits
disabled controls. No additional hidden token was present in these forms.

The network page uses `dhcp_state=0` for static and `1` for DHCP. Static form
fields contain dotted IPv4 values, including a dotted netmask and an explicit
gateway. The UI validates address syntax and requires the gateway in the same
subnet. DHCP disables the address/mask/gateway controls, so its mutation body
would omit them. DHCP transition is outside scope. The page warns that an IP
change loses the connection; actual disconnect and persistence behavior are
not yet established.

The user page has blank account/password fields: it does **not** reliably
read back the current username. No user-state model or password readback is
provided. The mutation includes the username and two matching new-password
fields; no current-password field or hidden command was observed. JavaScript
requires username length 5..16 and letters/digits/underscore. Password inputs
have HTML `maxlength=20`, while submission JavaScript requires 6..16 and
ASCII letters/digits plus `<=>[]!@#$*().`. These are UI constraints; server
validation has not been tested. The UI explicitly requires re-login after
account change. Same-username password rotation is the intended future scope.

Network and user callbacks test `code == 0`; network failure displays `data`.
The save callback shows success without inspecting the code, so production
code deliberately requires the known JSON success envelope instead. No
management-specific failure envelope has been induced on hardware; generic
library auth codes do not constitute management mutation evidence. Reboot
has no response-inspection callback and refreshes after three seconds; this
is not a proven reboot deadline or success condition.

## Implementation boundaries

Typed network readback and pure payload builders are internal components.
`save_config` sends one configuration POST and accepts only the observed
success envelope. Neither explicit expiry nor connection ambiguity causes a
second management POST. No reboot operation is exposed before live testing;
its pure payload contract is source-backed only. No high-level network or
credential transition is added to `JTComSwitch` or `DeviceConfig`.

`JTComCredentials.password` is excluded from repr. Management response data
is never echoed by the one-shot response validator. Future credential
transition work must additionally sanitize transport and authentication
failures and verify secret-safe logs/results.
